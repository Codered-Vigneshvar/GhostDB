## SNOWFLAKE ARCHITECTURE — WHAT MAKES IT DIFFERENT

Memorize these before reasoning about any query plan:

1. NO INDEXES. Snowflake uses micro-partitions and clustering keys.
   DuckDB has no clustering keys either. Optimize through filter pushdown and join order — not index hints.

2. CTEs ARE NOT MATERIALIZED. If a CTE is referenced more than once, it executes more than once. This is the single most common performance trap in Snowflake SQL. Always detect multi-reference CTEs and restructure them into a single reference or flag them.

3. COLUMNAR STORAGE. Only referenced columns are scanned. SELECT * is never acceptable — it forces full column scans.

4. QUALIFY REPLACES SUBQUERY DEDUPLICATION. The pattern:
     SELECT * FROM (SELECT *, ROW_NUMBER() OVER (...) AS rn FROM t) WHERE rn = 1
   must always be rewritten as:
     SELECT * FROM t QUALIFY ROW_NUMBER() OVER (...) = 1

5. UNION DOES A HIDDEN DISTINCT. Always use UNION ALL unless deduplication is explicitly required by the query's intent.

6. FUNCTIONS ON FILTER COLUMNS DESTROY PRUNING.
   WHERE DATE(ts) = '2025-01-15'  ← destroys partition pruning
   WHERE ts >= '2025-01-15' AND ts < '2025-01-16'  ← correct

7. IMPLICIT CASTING PREVENTS PRUNING.
   WHERE event_id = '12345'  ← event_id is INT, this casts every row
   WHERE event_id = 12345    ← correct

STEP 3 — REWRITE RULES (APPLY ALL THAT ARE RELEVANT)

FILTER PUSHDOWN
Push WHERE predicates as early as possible — into CTEs before joins, never after. Use explicit CTEs to make this visible:
```sql
  WITH filtered_orders AS (
      SELECT order_id, customer_id, amount
      FROM orders
      WHERE order_date >= '2025-01-01'
  ),
  us_customers AS (
      SELECT customer_id, name
      FROM customers
      WHERE region = 'US'
  )
  SELECT fo.order_id, uc.name
  FROM filtered_orders fo
  JOIN us_customers uc ON fo.customer_id = uc.customer_id;
```

ELIMINATE FUNCTIONS ON FILTER COLUMNS
  BAD:  WHERE DATE(event_timestamp) = '2025-01-15'
  GOOD: WHERE event_timestamp >= '2025-01-15' AND event_timestamp < '2025-01-16'

FIX IMPLICIT CASTING
  BAD:  WHERE event_id = '12345'   ← string vs INT column
  GOOD: WHERE event_id = 12345

REPLACE SUBQUERY DEDUPLICATION WITH QUALIFY
  BAD:
    SELECT * FROM (
        SELECT *, ROW_NUMBER() OVER (PARTITION BY id ORDER BY ts DESC) AS rn
        FROM events
    ) WHERE rn = 1;
  GOOD:
    SELECT * FROM events
    QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY ts DESC) = 1;

ELIMINATE CTE MULTI-REFERENCE
  BAD:
    WITH agg AS (SELECT customer_id, SUM(amount) AS total FROM orders GROUP BY 1)
    SELECT 'high' FROM agg WHERE total > 10000
    UNION ALL
    SELECT 'low'  FROM agg WHERE total <= 10000;
  GOOD:
    WITH agg AS (SELECT customer_id, SUM(amount) AS total FROM orders GROUP BY 1)
    SELECT CASE WHEN total > 10000 THEN 'high' ELSE 'low' END AS segment, COUNT(*)
    FROM agg
    GROUP BY segment;

ELIMINATE CORRELATED SUBQUERIES
  BAD:
    SELECT o.order_id,
           (SELECT MAX(o2.amount) FROM orders o2
            WHERE o2.customer_id = o.customer_id) AS max_amt
    FROM orders o;
  GOOD:
    SELECT order_id,
           MAX(amount) OVER (PARTITION BY customer_id) AS max_amt
    FROM orders;

ALIGN WINDOW FUNCTION SPECS TO SHARE SORT PASSES
  BAD:
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY event_time)
    SUM(amount)  OVER (PARTITION BY user_id ORDER BY event_date)
  GOOD:
    WINDOW w AS (PARTITION BY user_id ORDER BY event_time)
    ROW_NUMBER() OVER w
    LAG(event_time) OVER w
